# Dreame Local Agent

[English](README.en.md)

Локальный сервис для пылесосов Dreame с root-доступом: управление без облака из браузера или из умного дома. Проверен на Dreame X50 Pioneer Edition (R2505), прошивка 4.3.9_2021. Способ получить root сервис не предоставляет: он ставится на уже разблокированный робот.

Агент написан на Go, работает **на самом пылесосе**, вызывает штатный `avacmd` и предоставляет HTTP API и встроенный веб-интерфейс. Отдельный компьютер для работы не нужен.

## Возможности

- Состояние, уборка всего дома, комнат, зоны и точки, станция (выгрузка, мойка и сушка салфеток), мощность и громкость.
- Карта: сохранённая карта с комнатами, положение робота и пройденный путь во время уборки, объединение и разделение комнат, пороги, виртуальные стены, запретные зоны и зоны без влажной уборки, настройки уборки по комнатам.
- Расходники с ресурсом и сбросом, статистика, режим «не беспокоить», история уборок, понятные тексты ошибок, все настройки, которые отдаёт робот.
- Сам определяет модель и прошивку и показывает только то, что робот поддерживает; на незнакомой прошивке только читает.
- Поток событий, токены с правами чтения и управления, обновление агента из браузера с автоматическим откатом.
- Модули, которые ставятся из веб-интерфейса: [MQTT и Home Assistant](../dreame-module-mqtt), [региональная защита](../dreame-module-region).
- Голоса: переключение встроенных (EN, JA, KO, ZH), загрузка своих пакетов озвучки, прослушивание фраз по номерам — [как готовить пакет](docs/voice-packs.md).
- Настройка Wi-Fi и captive portal в режиме точки доступа.

Команды карты и станции проверены на R2505; уборка зоны и точки, история и путь робота пока проверены только тестами.

## API для адаптеров (`/api/v1`)

Все запросы с заголовком `Authorization: Bearer <token>`, ответ `{"result": ...}` или `{"error": ...}`.

- `GET /api/v1/state` — кэш состояния. Агент сам опрашивает робот раз в 5 с и сразу после команды, клиенты робот не нагружают. Поля: `activity` (`cleaning|paused|returning|docked|idle|error`), `status`/`status_name`, `battery`, `charging`, `suction`, `water`, `station`, `volume`, `error`, `region`, `region_code`, `cleaning_time` (мин) и `cleaned_area` (м²) текущей или последней уборки. Свойства, на которые робот не ответил, отсутствуют. `stale: true` — последний опрос не удался, `seq` растёт при каждом изменении. Раз в минуту к снимку добавляются `consumables` (`{"filter": {"left": %, "hours": ч}}` — только то, что отдаёт модель), `stats` (`cleanings`, `minutes`, `area` м²) и `dnd` (`enabled`, `start`, `end`); `error_name` — постоянное машинное имя кода ошибки (таблицы Tasshack, 122 — `unknown_warning`), `error_text`/`error_text_en` — текст ошибки из приложения Dreame; `device_capability` — маска возможностей, которую робот сообщает сам (4/83). Рядом со `state` — `command`: последняя принятая роботом команда (`name`, `at`, `outcome`). `outcome`: `pending` — ждём, `executed` — состояние робота показало результат (уборка началась, пауза, остановка, едет на базу, мощность или громкость сменились), `unknown` — за 30 с не показало, `accepted` — у команды нет видимого результата (найти, сбросы, настройки, станция).
- `GET /api/v1/capabilities` — `device_capability`: расшифровка 4/83 (`video_monitor`, `quick_command`, `streamer_and_ai`, `smart_charge`, `record_sound`); модель и прошивка, совпадение прошивки с проверенным профилем (`firmware.verified`), аппаратная таблица модели из самой прошивки (`/ava/conf/dconf_runtime.json`), читаемые свойства и доступность команд.
- `POST /api/v1/command` — `{"name": "start|pause|stop|dock|locate|mapping|empty|wash_mop|dry_start|dry_stop"}`, `{"name": "set_suction|set_volume", "value": N}`, `{"name": "clean_rooms", "rooms": [ids], "repeats": 1..3, "suction": 0..3, "water": 1..3}`, `{"name": "clean_zone", "zones": [[x0, y0, x1, y1]], "repeats", "suction", "water"}` (до 5 прямоугольников в мм карты, не меньше 30 см), `{"name": "clean_spot", "points": [[x, y]], "repeats", "suction", "water"}` (до 3 точек), `{"name": "reset_consumable", "consumable": "filter"}`, `{"name": "set_dnd", "enabled": true, "start": "22:00", "end": "08:00"}`, `{"name": "set_schedule", "id": N, "enabled": true, "time": "08:30", "days": "0111110", "rooms": [ids], "repeats", "suction", "water"}` (дни — семь цифр 0/1 с воскресенья, `0000000` — один раз; без `id` добавляет, без `rooms` — весь дом, при правке без `rooms` уборка задачи сохраняется; список — `schedules` в состоянии), `{"name": "delete_schedule", "id": N}`, `{"name": "remote_move", "velocity": -600..600, "rotation": -360..360}` (ручное управление, короткий шаг на каждую команду: первая сводит робот с базы, статус 13 `remote_control`, через ~15 с без команд он останавливается). Те же правила, что у `/rpc`: нужен `allow_control`, поддерживается `X-Dreame-Request-ID`, ненулевой код робота возвращается ошибкой. Команда блокируется, только если аппаратная таблица явно говорит, что узла нет.

- `GET /api/v1/map.png` — картинка сохранённой карты (комнаты, станция; во время уборки — робот, путь, вымытый пол и убираемая зона).
- `GET /api/v1/map` — калибровка этой картинки (`calibration_points`: три точки «миллиметры робота → пиксели», формат карточки xiaomi-vacuum-map-card) и комнаты с центрами в миллиметрах.
- `GET /api/v1/settings` — настройки из раздела «Настройки» панели, которые есть у робота, с текущими значениями; изменить: команда `{"name":"set_setting","setting":"<id>","to":<значение>}`.
- `GET /api/v1/voice` — голоса робота (`current`, `voices`: `id`, `builtin`, `files`); `GET /api/v1/voice/phrases?id=` — номера фраз голоса, `GET /api/v1/voice/phrase?id=&n=` — файл фразы (`audio/ogg`); `POST /api/v1/voice/install?id=<код>` с архивом `.tar.gz` в теле, `POST /api/v1/voice/use`, `/remove` с `{"id"}`, `/play` с `{"number"}` (сказать фразу на роботе). Только основной токен; как готовить пакет и что значат номера — [docs/voice-packs.md](docs/voice-packs.md) (агент 0.27+).
- `GET /api/v1/logs` — последние 32 КБ журналов: агента (запуски и ошибки команд с кодом 5xx), обновления агента и каждого модуля (`source`, `text`, `size`). Только основной токен (агент 0.28+).
- Препятствия, распознанные ИИ-камерой: `local.map_view` отдаёт `obstacles` (`[x, y, тип, уверенность %]`, миллиметры робота) и `obstacles_at` — время уборки, в которой они найдены. Панель рисует их значками, `map.png` для Home Assistant — кружками (красные — провода, носки и другое, на чём робот может застрять или что размажет). Агент 0.29+.
- `GET /api/v1/history` — история уборок, новые сверху: `start`, `end`, `mode`, `result` (`docked`/`idle`/`error`), `error`, `minutes`, `area`. Прошивка хранит записи только для облака, поэтому историю ведёт агент: время и площадь — разница общих счётчиков робота за уборку; уборки, прошедшие без агента, в неё не попадают.
- `GET /api/v1/events` — тот же снимок потоком Server-Sent Events: сразу текущий, затем при каждом изменении (`id: <seq>`, `event: state`, `data: <снимок>`), комментарий-пинг раз в 20 с. Не больше 8 потоков одновременно.

`/rpc` служит веб-интерфейсу и отладке: свойства MIOT (`get_properties`, `set_properties`, `action`) и локальные методы — `local.map_view` (сохранённая карта, пороги, запреты, настройки комнат), `local.live_pose`, `local.thresholds`, `local.restrictions`, `local.room_settings`, `local.room_order` (`{"map_id", "revision", "rooms": [все комнаты по порядку]}`), `local.room_types`, `local.map_backup_status` (копии карты, состояние восстановления 6/11, список карт), `local.map_backup`, `local.map_restore` / `local.map_backup_delete` (`{"name"}`), `local.map_use` (`{"map_id"}`), `local.carpets` (`{"map_id", "revision", "carpets_added": [[x0, y0, x1, y1]], "carpets_ignored": [...]}`, оба списка целиком), `local.setting`, `local.wifi_status`, `local.wifi_setup`, `local.reboot`.

### Незнакомая прошивка

Агент сверяет файлы прошивки с проверенными профилями (`firmware.verified` в `capabilities`). На прошивке без профиля команды, запись настроек и правка карты отключены: агент только читает. Чтобы управлять таким роботом на свой риск, задай `"allow_unverified_firmware": true` в конфигурации. Обновление агента, модули, Wi-Fi и перезагрузка работают в любом случае. Чтобы добавить профиль, скачай в «Диагностике» отчёт о совместимости и пришли его — в нём модель, прошивка и хэши её файлов, без идентификатора робота.

### Токены с правами

Основной `token` из конфигурации даёт полный доступ. Для умного дома и других устройств создай отдельный токен в веб-интерфейсе («Доступ») или через `POST /api/v1/system/tokens` `{"name": "ha", "scope": "read|control"}`. Токен показывается один раз; в конфигурации хранится только его SHA-256. Список — `GET /api/v1/system/tokens`, отзыв — `DELETE /api/v1/system/tokens/<name>`; управлять токенами может только основной токен.

| Права | Доступно |
|---|---|
| `read` | `GET state`, `capabilities`, `events`; чтение через `/rpc` (свойства, карта, статус сети) |
| `control` | то же и `POST /api/v1/command` |
| основной токен | всё, включая модули, обновление агента, настройки, Wi-Fi, перезагрузку и запись через `/rpc` |

## Модули

Модуль — пакет `.tar.gz`, который ставится в веб-интерфейсе: «Модули» → «Установить модуль» → «Проверить пакет» → «Установить». Перед установкой панель показывает манифест, файлы и SHA-256 пакета. Подписей нет: модуль работает на роботе с правами root, ставь только из источника, которому доверяешь. Установка и удаление требуют `allow_control`.

Пакет распаковывается в `/data/dreame-local/modules/<name>/`. Содержимое:

- `manifest.json` — `name` (`a-z0-9_-`), `version`, `title`, необязательные `description`, `handler`, `panel`, `read_actions`, `firmware_messages`, `control`, `service`;
- `handler` — исполняемый файл (shell-скрипт или бинарник). Агент запускает `handler <действие>`: параметры JSON приходят в stdin, скалярные — ещё и в переменных `P_<ключ>`; ответ — JSON в stdout, ошибка — ненулевой код и `{"error": "..."}`. Окружение: `DREAME_MODULE_DIR` (папка модуля, при обновлении заменяется целиком), `DREAME_MODULE_DATA` (`/data/dreame-local/module-data/<name>`: сохраняется при обновлении, удаляется вместе с модулем), `DREAME_API`, `DREAME_MODULE_TOKEN`. Действия жизненного цикла: `check` (до установки, отказ отменяет её), `install` (после копирования, при ошибке возвращается прежняя версия; при обновлении `DREAME_MODULE_PREVIOUS` указывает на папку прежней версии), `uninstall` (перед удалением). Остальные действия вызываются как `POST /api/v1/m/<name>/<действие>`; без `allow_control` доступны только `read_actions`;
- `panel` — ES-модуль `export default function mount(element, ctx)`: `ctx.read/ctx.call(действие, параметры)`, `ctx.rpc(метод, параметры)`, `ctx.onState(fn)`, `ctx.toast(текст, ошибка)`;
- `service` — исполняемый файл, который агент держит запущенным как `<service> run` с тем же окружением: перезапускает при сбое (пауза от 2 с до 1 мин), останавливает (SIGTERM) при обновлении, удалении модуля и остановке агента. Вывод — в `service.log` в папке данных;
- `boot-env.sh` — подключается из хука загрузки робота до старта `ava` (например, чтобы предзагрузить библиотеку). Не должен завершать оболочку; действует после перезагрузки.

Токен модуля (`DREAME_MODULE_TOKEN`) выводится из основного токена: он не меняется при перезапуске агента и перестаёт действовать при удалении модуля или смене основного токена. Он даёт только `GET /api/v1/state`, `capabilities`, `events` и `POST /api/v1/firmware_message` — `avacmd msg_cvt` с `cmd` из `firmware_messages` манифеста и не более 7 скалярными полями. Ответа прошивки у этих сообщений нет: результат — «отправлено», а не «применено». С `"control": true` токен модуля может ещё и отправлять `POST /api/v1/command` и вызывать действия других модулей из их `read_actions` (`POST /api/v1/m/<модуль>/<действие>`, агент 0.26+); это показывается при проверке пакета.

Отдельные модули: [региональная защита](../dreame-module-region), [MQTT и Home Assistant](../dreame-module-mqtt) — каждый в своём репозитории.

API: `GET /api/v1/modules`, `POST /api/v1/modules/stage` (тело — пакет), `POST /api/v1/modules/install` (`{"id"}`), `POST /api/v1/modules/remove` (`{"name"}`).

## Обновление агента

Новая версия ставится в веб-интерфейсе: «Обновление агента» → выбрать файл → «Проверить файл» → «Обновить». ADB для этого не нужен, только первая установка (см. ниже).

- Агент принимает только исполняемый файл Linux под архитектуру робота, который отвечает на `--version` строкой `dreame-local-agent <версия>`.
- Замену делает отдельный процесс-помощник (тот же бинарник с `--apply-update`): останавливает агент, ставит новый файл, прежний сохраняет как `dreame-local-agent.previous` и ждёт до 45 с, пока новая версия ответит своей версией на `/api/v1/capabilities`. Если не ответила — возвращает прежнюю, а новую откладывает в `dreame-local-agent.failed`. Резервная копия для ручного отката при этом сохраняется.
- «Вернуть версию …» ставит `dreame-local-agent.previous` тем же способом.
- Обновляются только бинарник и встроенный в него веб-интерфейс; `start.sh`, `stop.sh`, `boot-env.sh` и хук загрузки остаются прежними.

API (нужен `allow_control`): `GET /api/v1/system/update`, `POST /api/v1/system/update/stage` (тело — файл), `POST /api/v1/system/update/apply` (`{"source": "staged" | "previous"}`). Результат последнего обновления — в `/data/dreame-local/update-result.json`.

Версию сборки задаёт `-ldflags "-X main.version=..."`.

## Сборка

Нужен Go 1.24 или новее. Для целевого устройства требуется Linux ARM64:

```sh
cd agent
go test ./...
go vet ./...
CGO_ENABLED=0 GOOS=linux GOARCH=arm64 go build -trimpath -buildvcs=false -ldflags='-s -w -buildid=' -o dreame-local-agent-linux-arm64 .
```

Релизная сборка с версией из `agent/main.go` и SHA-256: `sh build.sh` → `dist/dreame-local-agent-<версия>-linux-arm64` и `.sha256`. На GitHub (`.github/workflows/ci.yml`) тесты идут при каждой отправке кода, а тег `v<версия>` публикует релиз с этими файлами; версия тега должна совпадать с версией агента.

## Установка

Нужны ADB с root-доступом к роботу и сборка агента (`sh build.sh`, см. выше). Одна команда:

```sh
python3 tools/install_agent.py --serial ROBOT_IP:4567
```

Если файла конфигурации (`bridge/config.json` или указанный в `--config`) ещё нет, установщик сам читает с робота модель, `did` и `mac`, создаёт случайный API-токен и сохраняет конфигурацию с правами 600. **Не публикуй этот файл.** С `--read-only` управление выключено: только состояние и карта. При повторной установке поля конфигурации на роботе, которыми установщик не управляет (дополнительные токены, `allow_unverified_firmware`), сохраняются. В конце установщик показывает, совпала ли прошивка с проверенным профилем и доступно ли управление.

Установщик проверяет root, ARM64 и идентичность устройства, затем развёртывает агент в `/data/dreame-local`, проверяет SHA-256 и HTTP-ответ. При обычном режиме добавляет в существующий `/data/test/ava.sh` запуск агента и подключение `boot-env.sh` модулей, сохраняя резервную копию. Обновление прошивки переименовывает `ava.sh` в `ava.sh_ok`: после него агент и модули не запускаются, пока хук не восстановлен. Для ручного запуска без изменения boot hook используй `--no-boot-hook`.

Веб-интерфейс после запуска: `http://ROBOT_IP:8765/`.
Не открывай порт 8765 в интернет: интерфейс предназначен для доверенной LAN.

## Тесты

Контракт ошибок операций карты и разрешения для map request описаны в [docs/map-results.md](docs/map-results.md). Для карты одного внешнего code0 недостаточно: проверяется отдельный operation result, а неизвестный исход не повторяется автоматически.

```sh
cd agent && go test ./... && go vet ./...
cd .. && python3 -m unittest discover -s tests -p 'test_install_hook.py' -v
# Дополнительные UI-тесты используют Playwright:
node tests/test_command_results.cjs
node tests/test_web_ui.cjs
```

Go-тесты рассчитаны на Linux (`Setsid`, mock `avacmd` на Python). На Windows собери тестовый бинарник и запусти его в WSL:

```sh
cd agent && GOOS=linux GOARCH=amd64 go test -c -o agent.test . && wsl ./agent.test
```

## Состав

- `agent/` — Go-сервис, встроенный веб-интерфейс и shell-скрипты.
- `tools/install_agent.py` — установка через ADB, с проверками идентичности.
- `tools/configure.py` — подготовка конфигурации из локального диагностического отчёта.
- `tests/` — тесты веб-интерфейса и установщика.
- `bridge/config.example.json` — **только шаблон**, без личных данных и токенов.

Это репозиторий **исходников агента**, а не полного пакета `dreame-local`: внешний Python-мост и диагностические данные сюда не включены. Сведения об атрибуции находятся в `NOTICE.md` и файлах лицензий.
