# План развития

Составлен 2026-11-22. Этапы идут по порядку; защита от обновления прошивки — после всех этапов.

## Этап 1. Живая карта и положение робота

Сделано в 0.16.0: источник найден — во время уборки прошивка пишет полные кадры (`FRAME_TYPE=I`) в `/tmp/log/fds_tmp_file_0` и `_1` для заливки в облако (`fds_hook.sh`, журнал `/data/log/fds.log`). Агент читает свежий кадр (`local.live_pose`): положение робота и станции, путь `tr`; интерфейс рисует их поверх карты и обновляет каждые 3 с. Не проверено на настоящей уборке: формат пути и то, пишет ли прошивка кадры без облака. Картинка карты для Home Assistant — агент 0.18.0 (`/api/v1/map.png`) и MQTT 1.3.0 (сущность `image`). Живой кадр — 0.24.0: агент собирает сетку уборки (последний I-кадр плюс P-кадры: изменения складываются по модулю 256, пиксель = комната<<2 | флаги, 252 — стена; установлено по кадрам уборки 2026-11-22) и отдаёт в `local.live_pose` клетки, которых нет на сохранённой карте (`new_cells`); интерфейс закрашивает их. Проверено на роботе: на уборке коридора — одна новая клетка стены. Картинка для Home Assistant рисует их с агента 0.26.0 (в рамке сохранённой карты, чтобы калибровка не сдвигалась).

Проверено на уборках 2026-11-22 (агент 0.18–0.19): путь растёт от начала уборки, переживает смену журнала, картинка для Home Assistant рисует робота и путь. 0.19.0: вымытый пол закрашен синим по ширине тряпок (300 мм; полоса за порогом — тряпки действительно заезжают), повторные проходы темнее.

Сейчас интерфейс показывает только сохранённую карту: где робот и где он уже прошёл, не видно.

1. Найти источник: прошивка отправляет живую карту в облако; нужно найти, откуда её можно забрать на роботе (временные файлы или сообщения между процессами прошивки). Для этого владелец один раз запускает обычную уборку, агент только наблюдает.
2. Разобрать формат: к готовому разбору полных кадров сохранённой карты добавить промежуточные кадры с изменениями, положение робота и станции, пройденный путь.
3. Отдать живую карту в поток событий агента; в интерфейсе робот и маршрут видны во время уборки.
4. Картинка карты в Home Assistant через MQTT-модуль.

Риск: источник может оказаться недоступен без вмешательства в процесс прошивки — тогда остановиться и выбрать вариант.

Отчёт о совместимости (с хэшами файлов прошивки, без идентификатора робота) скачивается в «Диагностике».

MQTT 1.4 (агент 0.22): 80 настроек робота как переключатели/списки/числа, камера карты с калибровкой и комнатами для xiaomi-vacuum-map-card. Проверено на роботе: список настроек, калибровка, запись настройки через агент; карточка показывает карту с калибровкой (проверено владельцем); Платформа карточки `send_command` через MQTT не работает (Home Assistant не передаёт параметры-списки), поэтому MQTT 1.6.0 сам собирает текст карточки с режимами зоны, точки и комнат на `vacuum.send_command` с параметрами-словарём (панель модуля → «Карточка карты»); проверено 2026-11-22: команда в формате Home Assistant запустила уборку зоны в коридоре. MQTT 1.5.0: комнаты как сегменты пылесоса — в Home Assistant появилось «Сопоставить сегменты с пространствами» (проверено владельцем 2026-11-22), уборка через `vacuum.clean_area`.

- ~~Настройки уборки по комнатам~~ — агент 0.13.0: мощность, влажность, повторы и режим, проверено на роботе.
- ~~Точечная уборка~~ — команду Tasshack (статус 20, `points`) X50 принимает, но убирает всю комнату (испытано 2026-11-22, остановлено). С 0.21.0 `clean_spot` отправляет зону 1,5×1,5 м вокруг точки (обрезается краем карты); проверено 2026-11-22: робот убрал только квадрат, история 2 мин, 2 м².
- ~~Уборка зоны~~ — агент 0.15.0 (`{"areas":[[x0,y0,x1,y1,повторы,мощность,вода]]}`, статус 19); проверено 2026-11-22: робот убрал только зону 1,2×1,2 м, история 1 мин, 1 м². Прошивка возвращает зону в кадрах (`da2.areas`), 0.20.2 рисует её рамкой.
- Расписания (не нужны владельцу, отложены) — нужен образец из штатного приложения. Установлено по прошивке (`node_msg_cvt.so`, `MsgTimer`): свойство 8/2, записи `номер-включено-ЧЧ:ММ-дни-повтор-карта-режим-влажная-области` (разбор `%d-%d-%d:%d-%x-%d-%d-%d-%d-%1023s`), хранятся в `/data/config/ava/timer_task.db` (`clean_timer`). Дни — семь цифр 0/1 от воскресенья к субботе (робот проверяет разряд `6 − tm_wday`), `0` — разовый запуск, после него задача выключается. Не установлено: значения «режима» (связан с быстрыми командами `quick_cmd`) и формат «областей» (`selects`/`areas`); удаление — действие 8/1.
- ~~Камера робота~~ — модуль `dreame-module-camera` 1.0.0 (2026-11-22): показывает снимки фронтальной камеры, которые прошивка сама сохраняет во время уборки для сбора данных ИИ (`/data/ai_offline_collection`, JPEG 672×504, несколько последних); по умолчанию выключен. Проверено на роботе. Модуль 1.1.0 (2026-11-23): живой просмотр, примерно 1 кадр/с в панели. Захват `/dev/video0` (sc520cs, 864×480 NV21) — тот же источник, что у облачного `video_monitor` (`/ava/conf/video_monitor/recorder.cfg`). На это время горит индикатор камеры (`gpio229`). Работает, когда робот на базе и не спит: во сне питание датчика выключено. Отладочная команда `avacmd streamer '{"cmd":"open_camera"}'` его не включает. Действие трансляции `siid 10001 aiid 1` через `msg_cvt` возвращает −1: оно принимается только с облачной стороны. Модуль 1.2.0 (агент 0.25.0): просмотр работает и во время уборки. Захват проверен против ИИ: `/dev/video12`, через который ИИ берёт тот же датчик, и `/dev/video0` открывали и закрывали в обоих порядках, и второй поток держал 15 к/с. На уборке коридора 98 из 100 кадров дошли, ошибок робота нет. Ручное управление с видео: команда `remote_move` (4/15, формат Tasshack), в панели камеры кнопки и стрелки; проверено на роботе — съезд с базы, вперёд, поворот, назад, возврат на базу. В Home Assistant (MQTT 1.8.0, агент 0.26.0): камера «Camera» с переключателем «Camera stream» (2 кадра/с, выключается сам через 10 минут; сущности есть, только пока установлен модуль камеры) и кнопки движения; модуль с правом управления может звать действия чтения другого модуля. Проверено на роботе: кадры дошли до брокера, кнопки свели робота с базы и повернули. Снимки для ИИ (2026-11-23): отдельной настройки нет. Их пишет узел `recorder` прошивки (`ai_offline_img_path` в `/ava/conf/r2440.conf`). На базе их разбирает офлайн-ИИ: комнаты, животные, люди (`AIOfflineInfer`, `AIRoomSeg`, `AIHumanOffline` в `node_camera_ai.so`). Потом прошивка сама удаляет папку вместе с `ai_offline_collection_index.txt` и `ai_offline_picture_pose.txt`. Выгрузка идёт через облачный `impfile_upload`, без облака снимки не уходят. На уборке коридора 2026-11-23 снимков не было. Фото препятствий прошивка кладёт в `/data/image/upload/` для облака, гифки животных — в `/data/gifimage/`. С включённым «Фото препятствий» (4/22 бит 4) на уборке коридора препятствий и фото не было, ключа `ai_obstacle` в кадрах карты тоже. Показ фото препятствий не сделан: нечем проверить.
